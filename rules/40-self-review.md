## 编码纪律 · 写完后的自检清单

在声称完成之前，**重读自己的 diff** 并逐条对照。这一遍是专门用来抓"明显 bug"的，不是复述改动。

### 空值与边界
- 新增的解引用是否可能为 `null` / `undefined`？数组是否可能为空或越界？
- `?.` 和 `!` 非空断言是否掩盖了本应修复的问题？
- 边界值：`0`、`1`、空集合、首尾元素、超长输入、空字符串、负数、`NaN`。

### 错误路径
- 有没有未 `await` 的 Promise、被忽略的 rejection、fire-and-forget 的副作用？
- `catch` 是否吞掉了错误或只打了日志却继续往下走？
- 错误分支的返回值类型是否与正常分支一致？

### 契约变更
- 改了函数签名、返回值结构、默认值或配置键名？**所有**调用点是否同步更新（用 grep 或影响面分析工具查）？
- 改了公开 API 或数据结构？文档、类型声明、序列化格式是否同步？

### 状态与资源
- 共享可变状态、闭包捕获循环变量、缓存失效是否处理？
- 句柄 / 连接 / 订阅 / 定时器是否关闭？循环里是否重复做 IO？写操作是否幂等？

### 平台与并发
- Windows 路径分隔符与大小写敏感性、UTF-8 BOM、CRLF / LF、文件锁。
- 竞态条件、缺少 `await`、并发下共享状态的读写顺序。

### 安全
- 命令拼接注入、路径穿越（`..`）、未转义的用户输入进入 shell / SQL / HTML。
- 日志、错误信息、提交内容里是否泄露密钥或凭据。

### 最后三问
1. 如果这段代码在线上出错，第一个症状会是什么？我有没有测到那个路径？
2. 我是不是因为"觉得应该没问题"而跳过了某条验证？
3. 有没有哪一行是我复制来但没真正读懂的？如果有，删掉或读懂再留。
